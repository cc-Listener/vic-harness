# M1 三类缺陷的结构性修复方案

日期：2026-10-15。状态：**候选设计，未获实施确认**。产品基线 `3f525c4`；本文件不修改原规划、ADR、合同 schema、固定 expected 或历史评测结果。

## 用户决定与目标

用户已明确：人读初始化时序错误（F03）、普通入口误归共享封装（F04）、检查失败却报告通过，继续作为发布阻塞；另拟结构性修复方案。用户对 apple-tools 试用答复“无需重跑”。因此沿用已有试用及问题记录，不再执行该仓库；这不等于接受已有缺陷、人工体验验收通过或批准发布。

目标仍是可靠的项目事实与定位合同：保留准确时序、真实封装及普通符号导航，正确报告实际检查结果。不能通过删除时序描述、清空 LI、降低 expected 或无限重抽样消除表面失败。M1 尚未完成，M2/T10 不提前启动。

## 已有证据与结构缺口

| --- | --- | --- |
| F03 | 第四系列 f2r1 把同步静态依赖中的路由顶层创建编号排在 render 之后，两轮保留 | 已读质量门仍未遵循；路径数组和有限 coverage 不验证执行时序 |

第四冻结源 `9969f72` 的原 raw/L2 为 11/12，各 fixture 达到规定技术门。旧分数、原件和失败不更改。`3f525c4` 的 proxy 指导仅改善诊断可见性，尚无新行为回归。已有规则全文读取、独审和 RTK 正反例足以提出机制候选，但没有证明下面的新设计有效。

## 路线比较

| 路线 | 能增加的能力 | 主要限制与成本 | 建议 |
| --- | --- | --- | --- |
| A：保持单代理，增加结构化事实与呈现检查 | 捕获字段、证据引用、表/合同和结果摘要之间的机械矛盾 | 作者仍可在事实、阶段和分类中一致犯错；不能独立闭合 F03/F04 | 仅作辅助，不作为三项的完整修复 |
| B：确定性检查结果 + 源码优先的独立语义审查 | 真实退出状态由工具生成；独立上下文从源码核对最终产物和报告 | 增加一次审查及必要复核的模型成本；仍有漏判风险；需明确调整“不启动子代理”边界 | **推荐作为下一步有界实施候选** |
| C：后续增强方向 | 有限语言分析可证明部分顺序；受控宿主可强制审查和结果准入，两者可分别选用 | 分别需要解析/语言适配或受控写入/宿主集成；当前插件不具备这些保证 | 不与 M1 本轮捆绑，按实际需要分别另立设计 |

推荐 B 不把“另一个模型说通过”当真值。它改变的是证据产生过程：作者不再同时担任唯一的语义检查者，工具不再让作者手填执行状态。A 的机械检查可以复用，但不再用自洽等同正确；C 的强保证不能借 B 的命名宣称已经获得。

## 组件一：固定 Git 检查结果工具

先覆盖已出现的 Git 检查错误，不建立任意命令执行框架。拟新增 bootstrap 内部 Node helper；只在当前流程已选择运行该检查时使用，不新增 no-op 必跑 gate，也不运行包脚本、安装依赖或写目标文件。

- 输入必须指定目标根、比较模式 `index-to-worktree` 和逐文件路径；没有默认整库扫描。路径必须位于目标根内，拒绝目录、glob、pathspec magic、软链穿越和已知禁读配置。路径合法不等于所有权或读取授权，主会话仍须先划定允许集合。
- 使用固定 argv、无 shell；关闭外部 diff、textconv、fsmonitor 和分页器。只执行已审核的 Git 参数，不接受附加命令或任意参数注入。目标 guidance 要求 RTK 时走透明 proxy，不增加 RTK 依赖。
- 执行前确认实际工具/shim、仓库元数据与配置的执行资格；约束 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE`、对象目录及配置注入等环境重定向，确保实际比较属于指定根和 index。固定 argv 本身不证明这点。未审查的配置 include、工具行为或元数据来源使目标/只读性无法确认时不执行，明确未检查；不为核验读取原禁读资产，不关闭 Git 自身所有权保护，不初始化或提交目标仓库。
- 由工具从实际子进程生成 `status`、`exit_code`、`signal`、超时/启动错误/输出截断、精确比较范围及分离诊断；禁止从模型传入这些结果。成功只允许进程正常结束、退出 0 且输出完整。
- 结果标明实际观察的是直接 Git 还是 RTK proxy 进程。proxy 模式只直接捕获代理进程的退出状态，不虚构对内部 Git 子进程的直接观察；退出传播语义未确认时保持未确认，不能把外层退出码或 helper 自身退出码偷换成内部 Git 原始退出码。
- `failed`、`timeout`、`error`、`incomplete` 均不能映射为通过。缺 Git、非仓库、信号退出、状态未知、输出截断等必须明确报告，不以空输出推断成功。
- 输出同时给出规范中文摘要，留在工具返回与会话中；不在目标仓库写运行日志或状态文件。受保护尾空行导致失败时保留原字节，如实报告，不自动修复外部段。
- 明确未检查 staged-only 差异、untracked 文件及未选路径。退出 0 只支持列出的 tracked 文件在 index→worktree 范围内通过，不能支持“全树检查通过”或“所有验证通过”。

这个工具能保证自己输出的结果来自真实子进程，但不能阻止上层模型忽略工具或在自由文本中再次错报。其他已有 gate/checker 的真实工具结果仍独立保存和报告；未纳入固定工具的命令不获得新的真实性保证。

## 组件二：独立语义审查

候选流程：主会话划定调查范围 → 一个全新审查上下文先独立核对源码 → 主会话生成产物并执行确定性检查 → 同一审查上下文读取实际产物、核对语义与声明 → 主会话定向修正并复核 → 交付。源码阶段不传作者候选分类和自评，减少标签锚定；已有文档可提供线索，但不作为无需核实的真值。该流程不是写入前的强制拦截器，候选错误可能先存在于授权自有文件中，交付前必须处理或如实报告未完成。现有 no-op 也可能保留错误，故审查涵盖本轮选定范围内的既有产物；发现真实错误可转 refresh，准确产物不为“审查过”而重写。

审查使用当前宿主真实提供的独立会话/子代理能力，必须为不继承作者推理与自评的全新上下文。优先使用可复用的现有只读审查能力；无法确认独立上下文或没有可调用能力时，不伪造工具/身份，不改配置，不自动安装。只能报告“独立语义审查未执行”，保留已知事实及未完成事项，由用户选择外部独立审查。手工写一份 `review_pass: true` 不构成审查。

审查输入包括本轮范围、候选文件及允许读取的源码入口、保护边界、需要核对的检查结果。作者的 facts、分类、阶段、排除说明和完成声明均是待核对陈述。审查者自行读取当前源码、文档和合同，核对入口及必要调用/消费位置；不能只看作者挑选的摘要或假设待审集合已经完整。不能访问 fixtures 的 expected、历史答案或其他 oracle 来指导产品行为。

| 审查面 | 必须核对的关系 | 必须保留的合法反例 |
| --- | --- | --- |
| F03 | 选定人读执行断言对应源码位置、模块机制和触发条件；静态依赖顶层求值、入口显式调用、注册与回调分别判断 | 动态 import、循环/顶层 await、注册时同步调用回调、多入口；证据不足明确未确认，不统一套同步 ESM |
| F04 | 每个共享表行及 LI 的真实用途、定义/公开入口/消费证据；人读与机器双向核对；空表也检查是否漏了真实封装 | 单调用者或尚无本仓调用者的真实公开 API、无 barrel 的直接导入、合法局部 client/interceptor、app 消费根封装且无独立 PA |
| 验证声明 | 最终声明逐项对应实际工具结果；失败及未执行项不能被其他绿色检查抵销 | 失败后真实成功重跑可以报告最终状态，但保留前次失败及准确范围；无证据时只报未验证 |

普通入口仍可出现在普通符号索引；LI 不要求与 PA 一一对应。共享表是否由 bootstrap 管理必须按原 ownership 调查，canonical 指针不授予段落修改权。审查发现问题只返回证据和建议，不改文件；所有修正由主会话在原授权范围内完成。

审查结果分 `supported`、`contradicted`、`unresolved`，并逐项引用源码/产物位置、已读文件和范围。这些是有证据的判断，不是无误的证明。存在反证时修复；存在未解决判断时明确列出，不签该范围语义完成；不能为获得 supported 删除准确事实或把所有内容降为未知。

第二回合还必须接收留在内存中的**最终检查结果与完成声明草稿**，包括每项状态、比较范围、未执行/失败/重跑及覆盖限制。 reviewer 核对它与可取得的真实工具事件，不只审文件。审后实质改变检查状态、范围或完成结论，必须占用剩余复核回合；预算已用完则如实未完成，不能增加一段未经审查的“全部通过”。声明草稿不写入目标仓库。该协议仍可能被模型违背，不是宿主强制的自由文本出口控制。

一次独立上下文包含两个必要回合（源码核对、实际产物核对），之后最多一个定向修正复核回合，合计上限三个审查模型回合。仍有问题则明确未完成并停止自动循环；不把多回合成本隐藏为一次调用，不无限重复到变绿。同一时刻最多一个 reviewer，不允许 reviewer 递归派生、执行业务命令或读写代理配置。检查通过不是完整产品通过，语义审查通过也不免除 checker、外部字节保护或真实 no-op。

## 真实性、权限与修订绑定

- 子代理返回须来自当前宿主真实调用结果；作者提交的 reviewer 名称、签名或 JSON 不能证明调用发生。当前开发环境具备协作工具，不代表所有安装用户的宿主具备相同能力。
- “只读审查”首先是职责边界。若宿主实际没有强制只读权限，不宣称沙箱隔离；不读取或修改 `.codex` 配置来制造该保证。具体宿主适配必须在实施中核验可用能力和失败路径。
- 记录本轮实际审过的文件内容绑定及检查结果对应范围；修改后旧结论失效，重读受影响文件后复核。绑定只证明版本对应，不证明语义真、读取完整或所有权。所有绑定留在会话/工具返回，目标仓库不新增 manifest、receipt 文件或日志。
- 宿主若不能向 reviewer 提供原始工具事件，主会话转述的执行记录不能标作独立可信证据。审查者不得通过重跑项目命令替代本次状态；相应验证声明保持未核实。评测 runner 的 JSONL 可在开发评测中验证此关系，但不是产品通用宿主 API。
- 独立上下文与原始执行事件是两项分别核验的能力：仅有前者时可以完成有源码依据的 F03/F04 审查，但不能签不实验证问题已闭合；有原始事件而无独立语义上下文，也不等于已完成分类/时序审查。各自缺项单独报告，不用一个 available 标志盖过差异。
- 纯文本 skill 不能强制阻断任意自由文本谎报，Node helper 也不能防止作者绕过它。真正的硬门需要在宿主侧控制写入/提交和验证来源，属于路线 C。B 只能作为有范围、可测量的错误检测与修正流程，不承诺绝对可靠。

## 保持不变的边界

合同 schema、固定 expected、旧评分、原 incident 和原证据不变；不新增第七个技能，不添加 npm 运行时依赖、软链或目标仓库平行配置。真正 no-op 继续零文件写入，`vic-agents` 的 no-op 不追加日志。apple-tools 原仓库和隔离副本均不重跑或修改。

本方案只修人读执行断言，不裁定 `entry_chain` 数组未来应表示组织主线还是完整关系图；该语义选择仍待用户，不能借本方案静默修改。保留真实加载期初始化与事件支路的事实，不能为匹配固定数组删事实。

## 实施与验收次序（候选拆分）

1. **固定检查工具及直接回归。** 拟改 `skills/vic-bootstrap/scripts/`、对应 reference、主 SKILL 和定向 tests。验证退出 0/非零、双流空的失败、信号/超时/缺 Git、截断、读取范围与特殊路径、保护字节保持、staged/untracked 明确未覆盖；覆盖环境重定向、未审配置 include、未知工具/shim 的拒绝或未执行路径。先看真正反例失败，再修复，不用仅断言文案存在的镜像测试。
2. **独立审查协议与宿主能力分支。** 拟改本技能 references、主 SKILL 及定向协议测试；若用户批准边界例外，才同步规格/决策记录和使用说明。先分别核验全新上下文能力和原始执行事件能力；核对真实调用/无能力/只读职责/禁止递归/旧修订失效/未决退出，包含审后把失败改为通过、扩大检查范围或完成声明的负例。协议测试不能证明语义审查正确。
3. **三类缺陷的独立行为验收。** 另定冻结版本和固定样本：历史错误产物为反例，准确版本及上述合法情形为对照。离线捕获/回放只能证明检测链，不证明新生成行为；关闭 F03/F04/不实声明还需最终修订真实运行的新证据。对新评测单独登记来源、轮数、语义判定和停止条件，完整保留失败，不重判第四系列，也不自动追加第五系列。

每个实现包使用 fresh 实现上下文与不同上下文独审，单独提交。任何需要的新模型运行都在方案确认后明确范围；当前仅做方案，不执行这些验证。不能因用户说 apple-tools 无需重跑，就虚构其他模型行为回归已通过；也不把该答复扩大为禁止将来经明确约定的定向评测。

## 需要确认的一处产品选择

是否选择路线 B，允许 bootstrap 在显式调用期间，使用宿主已有能力启动**最多一个只读职责的独立语义审查子代理**，并按上述条件复核一次？不会配置代理、触发业务任务或修改 `.codex`；缺能力时保留未完成，不自动装依赖或降为已通过。

这是对 [00-vision 的非目标](../../plan/00-vision.md) 与 [bootstrap 执行边界](../../../skills/vic-bootstrap/SKILL.md) 的限定调整。当前用户批准的是“另拟结构性修复方案”，没有批准具体边界例外。因此本候选尚未实施；拒绝该例外时保留路线 A 的有限辅助，并需采用外部独立审查或另议路线 C，不能把 A 宣称为完整语义修复。
