# 验证、交接与风险边界

质量门应能证明配置与当前任务相符；不要为小改动建立额外编排系统。

## 必需验证

`evaluation` 至少包含：

- `stage_evaluations`：谁验证哪项完成条件，使用什么具体命令或证据。
- `topology_evaluation`：相对于 single-agent，新增角色是否改善证据质量、降低风险或节省独立工作的时间。

配置修改至少检查 TOML 可解析、必需字段齐全、所用字段有当前官方依据、模型与推理设置兼容、引用路径存在，并确认无关设置未被覆盖。语法通过不等于当前 Codex 已加载配置；未验证运行时加载时如实说明。

调研和审查也要验证，但可以使用可追溯来源、具体发现和覆盖范围作为证据。不能确定验证方式时记录 `uncertainty`；仅将阻止必要工作的缺失项记为 `blockers`。

## 证据要求

`evidence_requirements` 按实际角色设置，不为未使用的角色填模板：

| 角色 | 最低证据 |
| --- | --- |
| `implementer` | 分配范围、改动文件、完成声明对应的验证结果 |
| `reviewer` | 具体发现或无发现结论、支撑证据、检查范围与未验证项 |
| `docs-verifier` | 已读取的权威来源、版本敏感细节、事实与推断的区分 |

涉及缺陷时要求复现或等价的失败证据；涉及数据、安全或权限时验证相关边界。审查无发现是有效结果，不强求编造问题。

## 必要时定义交接

真正需要阶段交接时，说明负责人、必要输入、输出工件和接受条件即可。优先交接文件路径、命令结果与明确发现，不依赖另一会话未收到的临时状态。

共享文件系统上的并行工作必须说明写入范围及冲突处理；上下文独立不能用来证明文件隔离。主会话负责综合子代理结果，并核对实际证据。

## 风险边界

`guardrails` 至少保留全局约束；有子代理时补充各角色的必要限制：

- 默认总数为 1–4，包含主会话；并发上限只计算子代理。
- 不因角色模板而扩张写入范围、权限或任务目标。
- reviewer 默认保持只读职责；文件内的只读配置不能代替对父运行时和连接器实际权限的检查。
- 不默认递归委派；确有需要时按当前运行时支持及任务边界单独判断，不生成未经当前官方参考确认的深度字段。
- 配置或证据失败时保留原有文件，修复可恢复问题；必要事实不足时停止依赖该事实的工作并说明缺口。
- 瞬时错误可以有限重试；不要无限重试、绕过权限或无声更换执行环境。

只有任务需要恢复策略时再细分错误类别，不要求每份摘要都生成完整错误处理表。

## 人工确认点

`human_checkpoints` 仅用于当前授权尚未覆盖的破坏性操作、权限扩大或其他实际高风险步骤。沿用已存在的授权；配置生成、普通角色升级、审查和可逆修复本身不要求额外确认。

必要确认点写明动作、原因和未确认时停止的依赖步骤，继续处理不受影响的工作。superpowers 状态为 `unknown` 时跳过可选 bridge，不因此阻塞官方 TOML 配置。
