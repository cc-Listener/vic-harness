根据用户目标推荐流程，允许模型自动调用。只推荐，不执行技能、建议命令、安装、文件写入或代理启动；推荐写入型技能不等于获得执行授权。

## 路由前确认

- 按当前会话实际可用技能列表确认名称、命名空间和可用性，回复使用发现的准确调用名。下表短名是识别提示，不是假定已安装。
- 外部技能未发现时说明“未安装，可选”，给出同一行的替代做法；旧文档、图谱或配置文件的存在不能证明技能已安装。无需安装外部插件即可继续核心流程，不复制其文本或流程。
- `vic-bootstrap`、`vic-agents` 只能由用户明确调用；配置代理不等于启动代理。外部技能也遵守其调用策略和用户已有授权。
- M1 的 `vic-learn` 为占位，记录/处理能力到 M2/v0.2/T13；`vic-prune` 为占位，剪枝/消融到 M3/v0.3/T17。此时不要推荐执行占位技能来完成工作。

## 决策表

| 场景 | 推荐流程 | 缺失或当前不可用时的可执行替代 |
|---|---|---|
| 新仓库或合同缺失 | `$vic-bootstrap` → 可选 `$setup-matt-pocock-skills` → 大仓库可选 `$understand` → 新增指针后由用户调用 `$vic-bootstrap` 刷新 | 外部未安装，可选；bootstrap 根据源码和现有文档建立合同。M1 无自动图谱吸收能力，新增事实须回源码核实。 |
| 决定是否用子代理、换模型配置 | `$vic-agents` | 单代理足够可零改动；无合同可独立 repo-scan，不强制初始化。若技能不可用，先人工核验官方模型/字段并提出配置建议。 |
| 想知道合同是否过期 | `$vic-check` | M1 仅检查当前结构/路径；drift 到 M2/T10。人工对照合同 evidence 与相关源码变更，检查通过不能证明未过期。 |
| 需求还模糊 | 可选 `$grill-with-docs` | 外部未安装，可选；直接澄清目标、约束、成功标准和关键未决问题，形成可审阅说明。 |
| 要拆任务 | 可选 `$to-spec` → `$to-tickets` | 外部未安装，可选；直接整理规格、依赖和逐项验收标准，形成任务清单；发布外部 issue 须在用户授权范围内。 |
| 实现 | 可选 `$implement` / `$tdd` | 外部未安装，可选；按明确规格做最小实现并运行相关测试与验证。 |
| 提交前 | 可选 `$understand-diff` → `$code-review` → `$pr` | 外部未安装，可选；直接检查 diff、依赖影响、正确性和安全性，运行相关验证并整理 PR 描述；创建 PR 须在用户授权范围内。 |
| 会话结束 | 可选 `$retro` → 未来 `$vic-learn` | retro 未安装，可选；M1 learn 占位，当前在回复中总结结果、失误、原因和下一步，用户可手工保存 incident。 |
| agent 刚犯了错 | 未来 `$vic-learn` 记录模式 | M1 learn 占位；当前在回复中记录发生了什么、证据、影响和改进建议，用户可手工保存。 |
| 换了模型 | `$vic-agents` 核验模型 → 未来 `$vic-prune` 消融测试 | M1 prune 占位；先核验模型，人工列候选约束，比较保留/移除候选后的既有评测结果；保留 guarded path/hard stop，不自动删除。 |
| 看不懂陌生代码 | 可选 `$understand-chat` / `$understand-explain` | 外部未安装，可选；直接从入口、调用链和测试读源码，用 rg 定位并给出源码证据。 |

## 回复

用简体中文说明匹配场景、推荐顺序、可用技能的准确调用名及选择理由；保留技术名。明确未安装项、M1 未实现能力和当前替代步骤。目标跨场景时组合最少必要步骤；信息不足时说明假设和关键缺口，不假装已执行推荐。
