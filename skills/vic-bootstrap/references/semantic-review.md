# 源码优先的独立语义审查

在调查与模式判定前读取。本协议补充 [artifacts.md](artifacts.md) 的语义质量门；[coverage.md](coverage.md) 的有限投影和产品 checker 各自保留原有范围，不能替代独立语义审查。只有用户显式调用 bootstrap 时，才适用最多一个 reviewer 的限定例外。

## 能力与边界

从当前会话实际暴露的原生工具、工具说明及可取得的真实调用返回发现能力，不凭工具名猜测、不编造宿主 API、不读取宿主配置或认证文件、不安装工具、不创建代理配置。优先复用宿主现有只读审查能力；新能力不得扩展为执行业务。

分别确认三项能力并在会话内保留依据，各自标明“未知 / 接口已声明 / 实际调用已确认”；工具元数据支持不等于本次调用成功，更不等于语义判断正确：

| 能力 | 足够依据 | 不足依据 |
| --- | --- | --- |
| 全新独立上下文 | 原生调用明确支持不继承作者历史/推理/自评，且本次实际按该方式启动并取得真实返回 | 新 agent 名称或 ID；工具名含 reviewer；作者声称 fresh；继承全部历史后要求“忽略” |
| 同一 reviewer 续传 | 实际返回可定位同一上下文，原生续传保留其源码审查结果 | 另建 reviewer；作者粘贴上一轮结论；将每次新建隐作一次审查 |
| 原始执行事件可见 | reviewer 可从宿主取得本轮真实工具调用与返回，辨认命令/范围/退出/超时/截断等来源 | 作者转贴 JSON、截图文字、执行摘要、自报 phase/shared/verified；只有 helper 自身退出码 |

这三项不能合成一个 `available` 标志。首次启动前先确认全新上下文和同一 reviewer 续传的接口明确支持本协议，再逐回合以真实返回确认实际调用。全新上下文接口缺失或无法确认时，报告“独立语义审查未执行”，保留已知事实与未完成范围，不用作者自审充数；续传接口缺失时不启动已知无法完成的两回合协议。实际续传失败则终止本次完整审查，源码阶段已取得的局部判断可报告，但不能另起第二个 reviewer 补轮。原始执行事件能力缺失时，仍可完成有源码依据的执行时序与封装用途核对，验证真实性单独保持未核实。复用只读审查角色仅复用能力，不能复用已参与本轮生成或继承作者判断的会话。

reviewer 是只读职责：只读本轮允许证据与候选产物，返回判断，不改文件、不运行项目命令、不派生代理、不读写代理配置，不访问评测标准答案、历史答案或其他 oracle 指导仓库事实判断。若宿主没有强制只读权限，明确职责约束不等于 OS 或工具沙箱；不修改 `.codex` 制造隔离声明。读取边界始终遵守 [ownership.md](ownership.md)；路径级发现不等于内容读取授权，哈希也属于读取。

## 一个上下文，两个必要回合，最多一次复核

预算按实际 reviewer 模型回合计数，不按工具次数或作者贴出的阶段计数。只允许同一 reviewer：源码回合 1 + 实际产物与最终声明回合 2 + 最多一个定向复核回合 3。同一时刻最多一个 reviewer；不能递归、换身份、重开会话或继续追加轮次来获得绿色结果。

主会话在首次启动前按宿主实际机制设定有限的等待期限，两个必要回合及复核共享已声明的预算。超时、取消、启动失败、工具错误、回合返回不完整均为该回合未完成，不能推断通过；不能自动重开 reviewer 重置预算。停止/取消只使用宿主已提供的机制；停止结果未知则如实报告，不声称已停止。等待超时不得以新 reviewer 并行替代。

### 回合 1：先从源码建立独立判断

主会话只传：目标根的会话内定位、本次调查问题及允许范围、源码入口/必要配置的路径线索、可读只读与禁读/保护边界、审查维度及预算。不传作者的事实集合、shared/classification/phase、候选分类、候选时序、自评、排除结论或完成结论；不继承作者历史来达到同样效果。

reviewer 自行读取入口和必要的定义、导入/导出、调用/消费位置，按实际语言/模块与触发机制调查。列出的源码入口只是起点，不能假定作者选集已完整；在允许范围内主动追踪必要证据，越界所需证据则返回 unresolved。先完成源码判断，再读取已有文档或合同取得补充线索；这些文档不自动成为真值。必要 guidance 与 ownership 边界可先读，但不能将其中的业务分类当事实。源码回合禁止读取作者整轮历史；不能为了取得执行事件导入作者消息、推理、自评或候选标签。事件通道若混合整轮消息，仅在产物/声明回合按实际允许范围使用，不反推源码回合独立性成立。

回合 1 返回：已读路径/位置、对应内容修订、已确认的执行/复用关系、合理反例与未确认点、后续产物须核对的事项。作者可据此定向补查和生成产物，但仍由主会话维护唯一事实集合；reviewer 不代写候选。

### 回合 2：实际产物与完整最终声明

主会话完成权限内写入、有限反馈、产品 checker 和本次已选择的其他检查后，续传同一 reviewer。`no-op` 也进入此回合，读取本轮选定范围内的既有实际产物，不能因为没有 diff 就略过语义审查。

输入：实际候选文件路径、原定范围及任何变化、保护边界、受影响源码/产物的当前内容绑定、本轮各检查的实际范围与真实结果来源，以及**完整最终回复草稿全文**。草稿覆盖 mode、实际变更、触发证据、深度/落位、保留项、未确认、所有检查状态、失败/未执行/重跑与覆盖限制；只留会话中，不写目标仓库。作者 facts 和排除说明可以作为待核对陈述，不能当独立证据。

reviewer 独立读取磁盘上的真实文件及必要消费位置，不只看作者挑选的 diff/摘要。核对源码→人读表/断言→机器字段，并从空表/空 LI 反向核对是否漏掉真实封装。准确的普通符号导航、真实加载期事实、事件支路和合法 LI 保留，不为消除问题删除事实或一律降为未知。

核对最终草稿中每项执行声明与宿主可见的真实事件：对应调用、结果、比较范围、未执行项、失败与后续重跑均匹配，其他绿色检查不能抵销失败。固定 Git 检查工具的使用、结果含义、proxy 限制与未覆盖项仅以 [git-check.md](git-check.md) 为准，不复制或另设状态转换；它只在本次原已选择该 Git 检查时调用，不新增 no-op gate，不升级为项目 VG。

原始事件不可取得时，作者转贴的工具结果只能帮助检查声明是否自相矛盾，不能证明命令真实发生或结果真实。即使转贴对象形状合法、带 version/agent ID/哈希/签名，也不得将验证声明判为已独立核实。reviewer 不重跑项目命令来替代本次原始事件；仅能签有独立源码证据的语义部分，并明确“执行真实性未核实”。原始事件仅部分可取时，逐条按实际来源、调用/命令、cwd/范围、退出/完成状态和所需输出完整性核实：足以支持的有限声明可报告已核对，缺字段或关联不明的相应声明保持 unresolved，不把部分能力说成完全不可读或全部真实性闭合。signal、timeout 或双流完整捕获语义未知时不补成成功，未提供 output 不自动等于空输出或完整捕获。

### 回合 3：仅一次定向复核

主会话修复 contradicted 项，或补充 unresolved 的必要证据后，向同一 reviewer 提交受影响的实际文件、修订、真实检查事件与更新后的完整最终草稿。reviewer 重读受影响证据并复核连带影响，不能沿用旧版结论。范围新增、文件变化、检查状态或完成结论改变均使相应旧结论失效；纯格式变化仍须确认没有改变待审语义。

若第二回合后发生实质修改，即使它只出现在最终回复，也占用这唯一复核。复核后仍 contradicted/unresolved、预算已用完、超时或取消时，报告未完成并停止自动循环；不增加第四回合、不换 reviewer、不附一段未经核对的“全部通过”。剩余预算不足完成必要回合也不能跳签。

## 必审关系与合法反例

| 审查面 | 必查 | 不能机械否定的情形 |
| --- | --- | --- |
| 人读执行断言 | 每个本轮选定的编号/箭头/阶段描述对应的源码位置、模块机制、触发条件；顶层求值、入口正文/显式调用、注册与回调分别核对 | 动态 import；循环依赖与顶层 await；注册 API 同步调用回调；条件执行、框架调度；多入口的不同触发关系。只声明有证据的关系，不能统一套同步无环 ESM |
| 共享用途及定位 | 共享表每行和每个 LI 的真实定义、公开入口、复用职责与必要消费证据；人读与机器双向核对；空集合是否遗漏真实封装 | 单调用者或尚无仓内调用者的真实公开 API；无 barrel 的直接导入；合法局部 client/interceptor/wrapper/hook；app 消费根封装且无独立 PA。LI 不要求与 PA 一一对应；缺包/调用者不是否定用途的充分条件 |
| 验证声明 | 最终全文逐项对应可取得的真实工具事件及实际范围，失败、未知、未执行、重跑分别保留 | 失败后确有成功重跑可说明最终状态，同时保留先前失败和两次范围；无事件只能报未核实，不因空输出、其他绿色检查或作者 JSON 变为通过 |

普通入口可留普通符号索引，但不能仅因可导入或被调用就进入共享封装表/LI。公开 API 的用途要由源码与接口职责支持，不以调用点数量判定。canonical 指针只解决定位，不授予文档段落写权限。人读时序与 `entry_chain` 的未来表示选择分开，不能借审查改变该字段含义。

## 返回与修订绑定

每个判断返回 `supported | contradicted | unresolved`，附审查面/具体声明、源码及实际产物位置、理由、已读集合、限制与对应修订；执行声明另写原始事件来源是否可见及实际支持范围。返回是证据判断，不是无误证明或自动准入标志，不新增 `review_pass` 验证器。

首次读取时在会话/工具返回中绑定实际内容版本（宿主可用的内容 ID、完整读回或允许集合的字节哈希，选择实际可取得方式），并记录路径及检查比较范围；只记录 Git HEAD 无法绑定未提交文件。绑定不证明语义、读取完整性或所有权。源/产物/声明/检查范围变化则相应结论失效，须在剩余回合重读复核。若无法确认实际审过哪版，则该范围 unresolved。

所有审查输入、返回、绑定和最终草稿只留会话/工具返回；目标仓库不新增 manifest、receipt、review 状态字段、运行摘要或日志，不更新日期/commit 伪造完成。审查回合记录不是产品新的持久合同。

## 模式、完成与诚实退出

按 [refresh-policy.md](refresh-policy.md) 判模式。准确现有产物保持 no-op，完整文件树零写入；审查不要求为了留下痕迹而重写，既有长期 uncertainty 不自动触发 refresh。审查发现本轮范围内真实的既有错误时，即使源码无改动，也按事实修正转 refresh，只改权限内缺口；未知所有权或受保护内容保留并报告未完成。

supported 仅支持列出的修订和范围。语义存在 contradicted 时修复；unresolved 时列出未解决范围，不签该范围语义完成，不用全部改为未知消除准确事实。缺少独立上下文、续传失败、原始事件不可见、预算耗尽与检查失败各自报告，不用一个完成标志掩盖差异。准确 no-op 可以零写，但不能同时声称尚未完成的独立审查已完成。

产物齐备、有限反馈无 gap、checker 零 error、Git 检查 passed、语义 supported 是不同结论，逐项报告；任何一个都不替代其他项，更不等同本次合同交付全部完成。该协议是有限的错误发现流程，纯文本 skill 与 helper 均不强制控制自由文本出口，不宣称绝对可靠。
